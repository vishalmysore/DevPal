Here is the functional and technical product specification for DevPal.

This document is structured to serve as your development roadmap, translating the browser-native architecture into concrete modules, data structures, and edge cases.

Product Requirements Document (PRD): DevPal
Project Status: Draft Specification

Architecture: 100% Client-Side (Serverless / WebGPU Native)

1. Product Overview & Core Value Prop
DevPal is a privacy-first, zero-infrastructure AI coding agent that runs entirely inside a standard web browser. By leveraging WebGPU for local inference and a virtual file system over IndexedDB, DevPal allows engineers to securely clone repositories, prompt an AI agent to write modifications, preview changes, and export standard .patch files without their code ever leaving their local machine.

Target Audience
Privacy-conscious developers handling sensitive IP.

Teams seeking zero-operational-cost AI coding features.

Indie hackers wanting an AI pair programmer without paying a recurring SaaS subscription.

2. System Architecture Layout
The client-side environment runs across two separate threads to keep the UI smooth and responsive:

[ MAIN UI THREAD ] 
   │ ── User Input (Repo URL, Prompt)
   │ ── File Tree Rendering (Radix/Shadcn)
   │ ── Diff Viewer UI (diff2html / Monaco)
   ▼
 ─── IPC (Inter-Thread Messaging) ───────────────────────────
   ▲
   ├─► [ WEB WORKER: Inference Layer ]
   │      └── WebLLM Engine (Qwen2.5-Coder / Wasm) ──► Direct WebGPU Access
   │
   └─► [ MAIN/WORKER Shared Storage ]
          └── IndexedDB ──► LightningFS ◄── isomorphic-git
3. Detailed Component Specification
Module A: The Storage & Git Workspace
Responsible for provisioning the virtual disk environment and executing version control processes.

Technology: isomorphic-git, @isomorphic-git/lightning-fs.

Requirements:

Sandboxed FS Initialization: Dynamically instantiate a distinct LightningFS namespace per project repository.

Shallow Clone Strategy: Execute clones using depth: 1 and singleBranch: true to prevent browser cache exhaustion on large histories.

Proxy Negotiation: Route all network requests through a highly available CORS proxy to satisfy GitHub/GitLab cross-origin request headers.

Diff Engine: Utilize git.walk matrices to evaluate physical differences between the virtual workspace directory (WORKdir) and the local git database tracking layer (STAGE/HEAD).

Module B: The WebLLM Inference Engine
Handles local compilation, pipeline execution, and token generation streams.

Technology: @mlc-ai/web-llm

Requirements:

WebGPU Validation: Guard rails checking navigator.gpu status before starting. If missing, drop down to a friendly UI notification suggesting a chromium-based alternative.

Model Pipeline Profile: Presets configured for Qwen2.5-Coder-7B-Instruct-q4f16_1-MLC.

Progressive Caching: Intercept the download lifecycle to cache binary weights inside the browser's Cache API native store, preventing network calls on subsequent launches.

Module C: Orchestration & Patch Management
The workflow coordinator translating user instructions into code alterations.

Technology: Vanilla JS Regex parser / String manipulators.

Requirements:

Context Extraction: Locate target files through manual selection or string-matching queries across the file tree.

Search-and-Replace Parsing Loop: Tokenize the model's output stream, isolating string matches wrapped in standard diff format blocks:

Plaintext
<<<<<<< SEARCH
[Target Line Matches]
=======
[AI Replacement Code]
>>>>>>> REPLACE
    *   **Error Safe Fallbacks:** If a `SEARCH` segment generated by the LLM doesn't map to a 1:1 character index match within the targeted source file, halt execution immediately without writing to storage, alerting the user to re-generate.

## 4. User Experience & Wireframe Flow

┌──────────────────────────────────────────────────────────────┐
│  DevPal 🤖🖲️                      [ WebGPU Status: Active🟢 ] │
├──────────────────────┬───────────────────────────────────────┤
│ 📂 Workspace         │ Prompt:                               │
│  └─► src/            │ ┌───────────────────────────────────┐ │
│       ├── main.js    │ │ Fix calculation bug in utils...   │ │
│       └── utils.js   │ └───────────────────────────────────┘ │
│                      │              [ ⚡ Run Local Agent ]   │
│                      ├───────────────────────────────────────┤
│                      │ Code Diff Preview:                    │
│                      │ 🟩 + function calculate(a, b) {       │
│                      │ 🟥 - function calc(a, b) {            │
│                      │                                       │
│                      │             [ 💾 Download .patch ]    │
└──────────────────────┴───────────────────────────────────────┘


1.  **Onboarding:** User arrives at the app. The system checks for WebGPU support and displays a "Download Engine Weights" dashboard showing network traffic stats.
2.  **Repository Setup:** User enters a public repository link (e.g., `[https://github.com/user/repo](https://github.com/user/repo)`). DevPal pulls the repository and generates a collapsible file directory tree on the left sidebar.
3.  **Agent Configuration:** User clicks a file within the sidebar to open it in a read-only viewport, typing their instructions into a floating query container.
4.  **Generation Phase:** User clicks "Run Agent". An overlay displays token velocity metrics alongside raw text streams.
5.  **Review & Export:** Once processing stops, the center pane flips to a split view highlighting modifications in green and red. The "Export Patch File" button at the top becomes clickable, generating a downloadable `.patch` file.

## 5. Technical Constraints & Mitigation Strategies

| Risk/Constraint | System Impact | DevPal Resolution Engineering |
| :--- | :--- | :--- |
| **Browser Out-Of-Memory (OOM)** | Tab crash due to large context windows or massive repositories. | Limit context assembly strictly to user-selected target files. Implement a structural block payload filter during git clone workflows to disregard binary files (`.png`, `.pdf`, `.mp4`). |
| **CORS Network Blocks** | `git clone` requests rejected by remote VCS hosts. | Configure a decentralized, stateless CORS reverse proxy engine. Allow power users to supply an optional personal proxy URL within the Settings tab. |
| **Inference Stalls (UI Freeze)** | Main thread lockout during deep token calculations. | Force all `WebLLM` runtime procedures to run inside a dedicated Background Web Worker via `CreateWorkerMLCEngine`. Communication uses structured message events (`postMessage`). |
